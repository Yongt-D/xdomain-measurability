### 2.2 臂的定义(**用第四章现成的 `--ablation` / `--fusion-mode`,不新写变体**)

## 3. ⚠️ 统计设计:先估方差,再定 n(**本章最容易翻车的地方**)

### 3.1 一个必须先纠正的错误认识

**episode 配对不能消除训练 seed 方差。** CRBS 的 ±2.56 IoU 是训练 seed 方差
(每个 seed 的 IoU 本已在 2997 张上聚合),episode 配对对它无效。
GAPL 台的 ±0.0023 之所以紧 10 倍,来自**训练设置**(固定 VGG16-BN 主干、100 张样本),
**不是**来自 episode 配对。

⇒ **本章新实验台(跨域 + K-shot)的 seed 方差是未知量,不得沿用任何一台的旧值。**

### 3.2 独立单元的定义(**写死**)

- **主判据的独立单元 = 训练 seed。** 不是 episode,不是图像。
- episode / support 集合的配对**只用于降低每个 seed 内部的测量噪声**,
  **不得**当作独立样本做检验(那是伪重复)。
- 每个 seed 内:所有臂使用**完全相同的 episode 列表与 support 集合**(同一 `--sample-seed`)。

### 3.3 两阶段(**第一阶段的数字不得进入任何结论**)

**阶段 0(方差标定,pilot)**
- 跑 **n₀ = 3** 个 seed 的 A 与 D+conf 两臂,只为估计配对差的 s_d;
- **该阶段的效应量、点估计一律不得写进论文、不得作为结果报告**,
  只允许把 s_d 写进本文件的 §9 变更日志;
- 若 pilot 的 s_d 使得"以 80% 功效检出 Δ=0.01 IoU"所需 n > **12**,
  ⇒ **判定该实验台不可用于显著性主张**,主判据降级为"方向一致性 + 效应量与置信区间",
  并在论文中明确写"本设定下 n 受算力限制,不做显著性断言"。

**阶段 1(判据 run)**
- n 由阶段 0 的 s_d 按 80% 功效反推,**上限 12**,下限 5;
- 两臂**同机**(起始指令 §8:判据 run 优先独享机);
- 跑完**全部** seed 才做检验,**不得中途看结果决定是否加 seed**。

### 3.4 统计量(**跑前写死**)

- 主检验:**配对 t 检验(双侧,α=0.05)** + **精确符号检验**,报 n、d̄、s_d、t、p、95% CI;
- **同时报**效应量与 CI,即使 p ≥ 0.05;
- 不做多重比较校正的补救性挑选;预先声明的对比只有两条:D+conf−A(主)、D+conf−B(次)。

# 附录 A:support 集构造规则(修订 1,2026-09-09,**仍在任何实验数字之前**)

写这一节的原因:preflight(`f65ed63`)暴露了三个 §2.1 没写死、但会影响结果的自由度。
按纪律,它们必须在**产出任何数字之前**定死。

## A.1 关键澄清:K 张目标域标注**只进推理,不进训练**

第四章 V5 的原型是在**前向时**由 support 池化得到的,不是训练出来的。因此本章:

- **训练只用源域 WHU**,目标域影像与标签**完全不参与训练、不参与早停、不参与模型选择**;
- K 张 Inria 标注**只在推理时**用于构造原型;
- 分割阈值仍在**源域验证集**上选定后冻结。

⇒ 本设定**比标准 SSDA 更严格**(SSDA 允许目标标注进入训练)。论文中必须这样表述,
**不得**自称 SSDA,只能说"与 SSDA 相比,我们的目标标注仅用于推理期原型构造"。
这也部分缓解了起始指令 §5"不得用目标域标签"的冲突:训练与阈值选择全程未用。

**由此得到一个重要的算力后果**:更换 support 集**不需要重训**,只需重跑推理。
故 support 抽样噪声可以廉价地被平均掉(见 A.4)。

## A.2 support 池

- **池 = Inria `train` split**。preflight 已断言其为 125 tiles × 81 = 10125,
  与测试集 37 tiles × 81 = 2997 **tile 级不相交**(ESWA 返修 R1-Q5 划分),
  ⇒ §2.1 的不相交要求**已由现有磁盘划分满足**,不需要新建划分,只需**断言**。
- 文件名格式 `<city><tile>_<patch>.tif`,城市 ∈ {austin, chicago, kitsap, tyrol-w, vienna}。
  划分脚本必须解析出 (city, tile) 并**断言** train/val/test 的 tile 集合两两不相交。

## A.3 support 候选的前景约束(**必须写死,否则原型退化**)

preflight 显示存在**整幅无前景**的 patch(label 全 0)。前景为空 ⇒ 前景原型无定义。

- **主设定**:候选须满足前景像素占比 **f ≥ 0.01**(即 ≥ 2621 / 512² 像素);
- **预先声明的敏感性检查**:f_min ∈ {0, 0.05} 各跑一次,作为稳健性附表;
- **K 张 support 尽可能来自不同 tile**(能满足时强制),避免 K 张全来自同一 tile
  导致 support 集不具代表性。

## A.4 抽样与配对(**写死**)

- K ∈ {1, 4, 8};
- 每个训练 seed 下,做 **R = 5 次独立 support 抽样**(因 A.1,只需重跑推理,代价低);
- **同一 seed、同一 R、同一 K 下,所有臂(A / B / D+conf)使用完全相同的 support 集与
  完全相同的 query 列表**;
- 上报量 = 对 R 取平均后的每 seed 值;**独立单元仍是训练 seed**(§3.2 不变),
  R 只用于压低 support 抽样噪声,**不得**当独立样本;
- 每次抽样的具体文件名清单落盘为 JSON,并记录 SHA256,**随结果一起 commit**。

## A.5 判负条件补充

若 f_min ∈ {0, 0.01, 0.05} 三档之间结论发生**方向性翻转**
⇒ 说明结论由 support 抽样规则驱动而非机制驱动,**不出正面判决**,照报。

# 附录 C:更正主臂定义(修订 3,2026-09-09,**仍在任何实验数字之前**)

## C.1 ⚠️ §2.2 的主臂写错了

§2.2 把主臂写成 `--ablation D --fusion-mode confidence`。**这是错的。**

核对第四章归档 `results/ch4_reference/v5_confidence_seed{0,1,2}.json` 的 `args`,
其真实配置是:

```
ablation = "C",  fusion_mode = "confidence",  sample_size = 100,
epochs = 160, batch_size = 4, lr = 3e-4, weight_decay = 1e-4,
support_shots = 4, enable_amp = true, no_pretrained = false
```

`ABLATIONS` 中 `C = (geometry=True, prototype_mode="mean", geometry_weighting=False)`,
`D = (…, geometry_weighting=True)`。dyt 上的 self-check 也印证:ablation C 下
`geometry_gain = 0.0`,即几何加权确实关闭。

⇒ **第四章通过六项因果检查、并给出 0.862081 ± 0.002342 的那个配置是 `C + confidence`,不是 D。**
若用 D 作主臂,就等于拿一个**未经因果验证的配置**去做"承接第四章已验证机制"的主张,
前提直接不成立。

## C.2 更正后的臂定义(**取代 §2.2 的表**)

| 臂 | `--ablation` | `--fusion-mode` | 含义 |
|---|---|---|---|
| **A** | `A` | `plain` | 无几何、无原型。**基线**(= 第四章表中的 A) |
| **B** | `B` | `plain` | 有几何模块、**无原型**。分离"几何模块"与"几何原型" |
| **C+conf** | `C` | `confidence` | **主臂** = 第四章已验证的 V5 confidence |

- **主对比:C+conf − A**;**次对比:C+conf − B**。
- `D + confidence`(开启几何加权)**降级为探索臂**,非主判据,
  且**不得**在主对比不利时用它顶替。

## C.3 其余超参一律与第四章对齐(**不得改**)

`sample_size=100, epochs=160, batch_size=4, lr=3e-4, weight_decay=1e-4,

# 附录 G:F.2 中 ① ④ 映射错误的更正(修订 7,2026-09-10,**在任何消融数字之前 commit**)

## G.1 事实

| 臂 | `geometry` | `prototype_mode` | `geometry_weighting` |
|---|---|---|---|
| A | False | none | False |
| B | **True** | none | False |
| **C(本章主臂)** | **True** | mean | **False** |
| D | True | mean | **True** |
| E | True | closed_loop | True |

`geometry_weighting` **只在臂 D/E 为真**。它控制两处(`:285-291`、`:526-544`):

## H.1 为什么需要它

`docs/判定_强制因果消融.md`:③ 三 seed 全不过,归一化熵 H̄ = 0.9965–0.9982(K=4 均匀熵 = 1.0),
但 SD(H) = 2.4e-3 – 4.6e-3 > 1e-4 —— `a_k` **不是常数,只是偏离均匀极小**。

"这点极小的偏离是否承载性能"**不能由熵阈值回答**。③ 的阈值只是筛查;
决定性检验是:**把 `a_k` 强制置为均匀,其余一切不变,看跨域 IoU 是否变化。**

## H.2 实现(运行时干预,不改 fork 文件)

把 `PrototypeHead.support_temperature` 在**推理时**置为 `1e6`。
因 `support_scores = cos(q, s_k) / |T|.clamp_min(0.05)`,`cos ∈ [−1, 1]` ⇒ 分数落入 `[−1e−6, 1e−6]`
⇒ softmax 与均匀分布的偏差为 O(1e−6)。脚本**必须打印实际达到的熵**以自证已达均匀(判据见 H.3 的 U0)。

其余全部不变:同一 checkpoint、同一**源域验证集冻结阈值**、同一 support 清单、同一 query 全集。

## H.3 判据(**跑前写死**)

| 编号 | 判据 |
|---|---|
| **U0**(自证) | 干预后归一化熵 H̄ > 0.99999。不满足 ⇒ 干预未生效,**结果作废,不得判读** |
| **U1**(主判据) | `\|IoU_uniform − IoU_base\|` **< 0.0037**,三 seed 全满足 ⇒ 判定 `a_k` 加权路径**功能惰性**(可用等权平均替代) |
| **U2** | 逐 seed 报告 Δ 的**符号与量级**,以及 base 通道的 `max_k a_k` 与 `1/K` 的偏离 |
| **U3**(反向) | 任一 seed `\|Δ\| ≥ 0.0037` ⇒ 该微小偏离**确实承载性能**,③ 的结论收窄为"熵接近上界但非惰性"。<br>**不得**因此反过来宣称 ③ 通过 —— ③ 的阈值判定已经落定,不重开 |

**U1 阈值 0.0037 的出处**:阶段 0b 中 C 臂 support 抽样标准差的**最小值**(seed1,见
`docs/判定_阶段0b标定.md` §4)。即"小于本实验台自身重抽 support 的噪声底"。
该值是**仪器属性**,在本检验产出任何数字之前即已存在且已 commit。

## H.4 ⚠️ 禁止的过度解读(跑前写死)

移除 `a_k` 加权路径实际节省的参数**只有 1 个标量**(`support_temperature`);
`query_global` / `support_global` 是**无参数**的均值 + L2 归一化。
⇒ **不得**把本检验的任何结果用作"本章方法参数量更小"的主张。
本检验的价值是**机制定位**(哪一个子部件是惰性的)与**结构简化**,**不是参数量**。

# 附录 I:原型可缓存推论及其检验(修订 9,2026-09-10,**在该检验任何数字之前 commit**)

## I.1 推论的来源

`docs/判定_ak均匀替换.md` 判定 `a_k` 加权路径**功能惰性**(U1 三 seed 全过)。
由此得到一个**可检验的工程推论**,而非新机制。

## I.2 查询无关性(代码级论证)

令 `a_k ≡ 1/K`。查 `src/gaplsegnet_v5_ch5.py`:

- `support_weight`(`:284-291`)只依赖 `support_importance`,而后者只由 support 特征算出;
- `shot_foreground` / `shot_background`(`:295-300`)只依赖 `support_features` 与 `support_mask`;
- `foreground = (shot_foreground * a_k).sum(1)`(`:309-310`)在 `a_k ≡ 1/K` 下退化为
  **对 shots 取平均** ⇒ **完全不含 `query_features`**。

⇒ **support 集合固定时,前景/背景原型是常量**,可一次算好并缓存。
`prototype_logits` 仍需 `query_features`,但那是**本来就要算的一次**编码。

**当前实现的开销**:`:444-450` 对**每个 query batch** 都把 `B×K` 张 support 送进 `extract_features`。
即每张 query 付 `1 + K` 次编码。缓存后降为 **1 次**。
(旁证:阶段 0b 实测评测耗时 A 臂 ≈ 50 s、C 臂 ≈ 213 s,比值 4.26,与 K=4 时的 `(1+K)/1 = 5`
在扣除共享的数据装载后一致。**该旁证不作为结论,结论以 I.4 的正式计时为准。**)

## I.3 精确性判据(**跑前写死**)

缓存版与原版在**同一 checkpoint、同一冻结阈值、同一 support 与 query 全集**下:

| 编号 | 判据 |
|---|---|
| **E1** | 二值预测**不一致像素比例 < 0.01%** |
| **E2** | `\|IoU_cached − IoU_uncached\| < 1e-4` |

两条任一不满足 ⇒ 缓存实现有误(而非"近似"),**修正实现后重跑,不得把差异解释为可接受误差**。

## I.4 计时协议(**跑前写死**)

- dyt / RTX 3090 **独占**,阶段 1 跑完之后执行(避免争用);
- `batch_size=4, num_workers=4`,预热 20 个 batch 后开始计时;
- 三种配置:**A 臂** / **C 臂原版** / **C 臂缓存版**;
- 每种重复 **3 次**,报**中位数**;
- **同时报告两种口径**:(a) 端到端墙钟(含数据装载);(b) `torch.cuda.synchronize()` 前后的
  纯 GPU 计算时间(排除数据装载)。数据装载在三种配置间共享,只报 (a) 会**稀释**比值,
  只报 (b) 会**夸大**实际收益 —— 故两者都报,论文中并列。

## I.5 可以主张与不可以主张的(**跑前写死**)

**可以**:在本章操作化的设定下(support 集合固定、K 张目标域标注),
查询条件化的 support 选择头**可证惰性**,因而原型可缓存,推理编码开销由 `1+K` 次降至 1 次。

**不可以**:
1. **不得**把"缓存"本身说成方法贡献 —— 固定量缓存是常规工程,**贡献是证明它无损**;
2. **不得**主张参数量更小(附录 H.4);
3. **不得**外推到逐 query 轮换 support 的 episodic 设定 —— 那里原型不是常量;
4. **在完成查新-4 之前,不得对"support 选择头退化"作任何新颖性主张。**

## I.6 查新-4(**前置条件,零 GPU,可在阶段 1 训练期间完成**)

检索题目:少样本分割 / 跨域少样本中,**support 选择注意力退化为均匀**是否已被报道;
以及"固定 support 下原型缓存"是否已被作为效率手段发表。
按 §4.1 的规程执行并写入 `docs/查新4_support选择退化_CH5Geo.md`,**先出判断再谈主张**。

### H_A:乘性协同(交互项)

> 交互效应 = (SG − S) − (C+conf − A),即**几何的增益是否依赖语义分支的状态**。

- **H_A 成立**:交互效应的方向在各 seed 一致,且 |交互效应| **>** 噪声底 0.0037;
- **H_A 不成立(可加)**:|交互效应| < 0.0037。

⚠️ **反向条款,不得回避**:若判为**可加**,则「协同」**不得**作为主张,
必须如实报告为"两轴贡献在本设定下近似可加"。
**理由(现在就写死)**:可加性框架(EMAP)正是我们自己在 ESWA 返修中建立的;
**不能只在对自己有利时使用它**。

### H_B:逐样本互补性(**与 H_A 并列预注册,非 H_A 失败后的补救**)

即使聚合效应可加,两轴仍可能**改善不同的样本**。本章已对每次评测落盘逐样本
tp/fp/fn/iou(`*.per_sample.json`),故该分析**无需新增任何实验**。

> 定义:令 `I_geo` = 几何轴使其 IoU 提升超过 δ 的样本集,`I_sem` 同理(δ 跑前定为 **0.02**)。
> **H_B 成立**:`|I_geo ∩ I_sem| / |I_geo ∪ I_sem|`(Jaccard)**显著低于**
> 在两集合大小固定下随机重叠的期望值,且该方向在各 seed 一致。

H_B 成立 ⇒ 可主张**功能互补**(两轴修好的是不同的图),这是"协同"的**实践含义**,
与 H_A 的乘性含义并列陈述,**不得混称**。

L1(受控再检验)+ L2(GSD 退化曲线)。**此结局现在就写下,以免事后有粉饰压力。**

# 附录 M:T2 阳性对照的替换(修订 13,2026-09-10,**在替换后的对照产出数字之前 commit**)

## M.1 为什么必须换

`scripts/abibe_text_pathway_check.py` 预注册的 T2 是:

**该对照现已被证明在原理上不可能通过。** 代码层面(全文核实):

- `models/backbone/janus_pro_extractor.py:402`:`image_features, edge_map = self.extract_image_features(images)`
  —— **只接受 `images`,不接受文本**;
- 同文件 `:406-412`:`processed_text_features = text_features.to(torch.float32)` —— 算出来了;
- 同文件 `:414-418`:返回 `{'image_features':…, 'text_features': processed_text_features, 'edge_map':…}`;

⇒ **文本特征在任何配置下都不influence输出**,故"janus 开启时文本应当有影响"这一前提为假。

# 附录 O:L2 下采样算子与执行参数(修订 15,2026-09-10,**在 L2 任何数字之前 commit**)

§5 要求「下采样算子跑前固定并写入脚本」,本附录固定之。

## O.1 算子(**跑前写死,不得事后更改**)

对目标域 Inria 的**图像**(不含标签),按 GSD 因子 `f = GSD / 0.3 ∈ {1, 2, 4, 8}`
(对应 **0.3 / 0.6 / 1.2 / 2.4 m**):

```
I_f = TF.resize(I, [512 // f, 512 // f], antialias=True)      # 存盘,无损 PNG
```

随后由**未经修改的** `BuildingDataset.__getitem__`(`src/gaplsegnet_v5_ch5.py:95`)
以 `TF.resize(..., [512, 512], antialias=True)` 升回 512。
⇒ **模型输入恒为 512×512,但其信息量被降到 512/f 的水平。**

**标签不降采样**(保持原始 512),故 `f=1..8` 各点的**评测几何完全一致**,
IoU 之差只能来自输入信息量。

**support 图像同样降采样**(与 query 同 GSD)—— 操作化的是"整幅目标域影像都是这个 GSD",
而不是"只有查询图变糊"。

### O.1.1 为什么不选另一种操作化(如实记录)

另一种做法是把图像**与标签**一起降到 512/f 并在该尺寸上评测,使建筑物的**像素尺寸**变小。
**本章不选它**,理由:
(i) 标签重采样会破坏细小结构,引入与模型无关的伪影;
(ii) 各 GSD 点的评测几何将不再一致,IoU 不可直接并列;
(iii) 会改变输入尺寸,而 `BuildingDataset` 恒定 resize 到 512,规避它需要改 fork(§4⑥ 禁止)。

**代价必须写明**:本操作化下建筑物的**像素尺寸不变、信息量下降**;
故 L2 回答的是"**几何/外观线索对输入信息量下降的敏感度**",
**不是**"物体像素尺寸低于某阈值时先验失效"。
⚠️ **论文中不得**把 L2 的结果表述为后者。查新-2 §5.2 的候选主张若要成立,需另设实验。

## O.2 执行参数

- **臂**:A / B / **C+conf**(按附录 L.1 更正,原 §5 的 D+conf 系笔误);
- **checkpoint**:阶段 1 的 12 个 seed(L.3:纯推理,不重训);
- **K = 4,R = 1**:§5 已写明 L2 是描述性结果、不设显著性门槛;
  且 A/B 对 support 结构恒等(F.3),C 臂的 R 抽样噪声(0.0037)远小于本曲线关注的量级;
- **阈值**:每个 checkpoint 沿用其在**源域 WHU 验证集**上选定并冻结的阈值,
  **四个 GSD 点共用同一阈值**(不得逐 GSD 重选,否则等于用目标域信息调参);
- **机器**:附录 L.2 判为 **E1(`max|Δ| = 3.9e-5`)**,故允许在 30141 / 30007 执行;
  每条曲线整条在同一台机器上完成。

1. **能力下降**:模型确实分不出建筑了;

# 附录 P:L2 交叉形态的混淆排除对照(修订 16,2026-09-10,**在该对照产出数字之前 commit**)

### 对照 X(support 不降采样)

> query 用降采样视图(`f ∈ {1,2,4,8}`),**support 图像保持 0.3 m 原始分辨率**,
> 其余一切不变(同 checkpoint、同冻结阈值、同 manifest、同标签)。

| 结局 | 判读 |
|---|---|
| **X1** 对照下 C 的崩塌**基本消失**(C−A 在各 GSD 点不再显著为负) | 崩塌主因是 **support 退化**;⇒ **交叉形态不成立**,不得作为尺度主张的证据 |

- 8-连通连通域 → 实例面积 a(像素)。**尺寸层**(绝对阈值):S1 a<256;S2 256≤a<1024;S3 1024≤a<4096;S4 a≥4096(0.3 m 下分别约 <23 m²、23–92 m²、92–369 m²、≥369 m²);
- 正像素按到实例边界的欧氏距离分 **边缘带**(≤4 px)与 **内部**(>4 px);
- 负像素按到最近建筑的距离分 **近带**(≤4 px)与 **远区**(>4 px)。
共 10 个层:正像素 S1–S4 × {边缘, 内部} = 8 层;负像素 {近, 远} = 2 层。
每图每层记录:层内像素数 n、层内预测为正的像素数 p1。正层:tp = p1,fn = n − p1;负层:fp = p1。
⇒ 全图 tp/fp/fn 由各层求和得到,**必须**与 `results/l2/*.per_sample.json` 同 (臂, seed, f) 的逐图计数一致(同机逐位;跨机差 < 0.0005 IoU)。

阈值:**直接传入**该 checkpoint 在 L1 冻结的阈值(不重选,吸取 `判定_阶段1_L2与加宽诊断` §1.2 的教训)。
机制量:B、C 臂在 geometry2/3/4 上挂前向钩子,记录每图 DGM 残差相对幅度 r_i(三层平均;与消融④同定义);A 臂 r_i ≡ 0。

## T.4 假说与判据(n = 12 seed;"支持"需 ≥ 9/12;不作显著性断言)

记层内像素聚合 IoU 差 Δ_S = IoU_C(S) − IoU_A(S)(正层用 tp/(tp+fn+该层对应的 fp 无法归属 ⇒ 正层用 **召回率** R = tp/(tp+fn));负层用**假正率** FPR = fp/n。

- **H5a(尺寸)**:f=2 时,ΔR_S4 < ΔR_S1(C 相对 A 在最大实例上的召回损失更大)于 ≥ 9/12 seed。
- **H5b(内部 vs 边缘)**:f=2 时,ΔR_interior(S3∪S4)< ΔR_edge(S3∪S4)于 ≥ 9/12 seed(额外损失在大建筑**内部**)。
- **H5c(归因到几何模块还是原型)**:用 B 臂重复 H5a:若 B−A 也在 ≥ 9/12 seed 满足 ΔR_S4 < ΔR_S1 ⇒ 归因几何精化模块;若 B−A 不满足而 C−A 满足 ⇒ 归因原型/门控侧;都不满足 ⇒ H5a 本身不成立。
- **H5d(机制:DGM 残差)**:(i) C 臂每图 r_i 的中位数从 f=1 到 f=2 **上升**于 ≥ 9/12 seed;(ii) f=2 时 Spearman(r_i, 每图 R_C − R_A on S3∪S4)**< 0** 于 ≥ 9/12 seed(残差越大,大建筑召回损失越大)。
- **H5e(假正侧)**:f=2 时 ΔFPR_far(C−A)是否 > 0 于 ≥ 9/12 seed —— 探索性,无方向预设,只报。
- f=1 作对照;f=4/8 描述性报告。**任一假说不成立照报,不得改分层或阈值。**

# 附录 X:用 K 张 support 的标签重选阈值 —— 工作点增益能否被少样本标定收回(修订 24,2026-09-13,**在其任何数字之前 commit**)

## X.1 触发与性质

U.9/V 表明 Massachusetts 的 +0.08 中约 85% 是工作点效应,而 oracle 用了全部 query 标签,不可部署。审稿人会问"那怎么办"。本协议本来就有 K 张带标签的 support(K ∈ {1,4,8}),主协议禁止用它们选阈值(§3;为了隔离机制效应)。本附录**只作诊断**:若允许用这 K 张的标签在 0.05–0.95 上选阈值,(i) 基线 A 能收回多少 oracle 增益;(ii) C−A 是否随之缩到 MDE 以下。**不改主协议**,数字不进结果表(Q.4 同款边界),但可作为"少样本标定"的可部署替代写入讨论。

## X.2 设计(**写死**)

- 输入:已 commit 的加宽阈值诊断 JSON(`results/thrdiag_stage1`(Inria f=1)、`results/thrdiag_mass`(Massachusetts U 视图))中每 (臂, seed) 的 query 全集 IoU(阈值)曲线(0.05–0.95,`fmin0.01_K4_r0` 的 support)。
- 新计算:`scripts/support_calibrated_threshold.py` 对每 (臂, seed, 目标域, support 抽样 r∈0..4):把该抽样的 K=4 张 support patch 作为输入前向(C 臂的原型仍由同一组 support 构造 —— 这对 C 臂是**乐观**的,须披露),在同一网格上求 4 张合并 tp/fp/fn 的 IoU 最大阈值 t_sup(r);query IoU 取曲线在 t_sup(r) 处的值;A/B 的曲线与 support 无关,C 的曲线只有 r0 的(C 在 r≠0 处用 r0 曲线,披露为近似)。
- 报告量:IoU_sup = 5 次抽样均值;收回比例 ρ_rec = (IoU_sup − IoU_frozen)/(IoU_oracle − IoU_frozen)(oracle 增益为 0 时不定义);C−A 在 support 标定阈值下的逐 seed 差。
- 机器:本机 5080(只需前向 4 张 × 5 抽样 × 36 checkpoint × 2 域,分钟级)。

## X.3 判据(n = 12;≥ 9/12;不作显著性断言)

| 编号 | 问题 | 判据 |
|---|---|---|
| **X-H1** | 4 张 support 能否收回基线的工作点损失 | Massachusetts 上 A 的 ρ_rec ≥ 0.5 **≥ 9/12** ⇒ "少样本标定可收回大半";否则照报(Inria 同表只报) |
| **X-H2** | 标定后机制增益是否仍可测 | Massachusetts 上 C−A(两臂各用自己的 support 标定阈值)效应量 < MDE_mass(0.0289)⇒ "增益随标定消失";≥ MDE 且方向 ≥ 10/12 ⇒ "增益部分独立于标定" |
| X-E1(探索) | 抽样方差 | t_sup 的 5 次抽样 SD 与 IoU_sup 的抽样 SD(只报) |

## AA.2 规则(对 2026-09-16 之后任何新源域 / 新批次生效)

1. **主规则不变**:冻结阈值 = 源域 val 上 0.40–0.60(步 0.01)的 IoU argmax,并列取最小阈值;靶域标签不参与。

3. **无泄漏宽网格副策略**:同一源域 val 上 0.05–0.95(步 0.01,91 点)的 argmax(并列取最小)记为 t_wide;靶域在 t_wide 处的 IoU 与主策略并列报告(效应量、描述性 CI、方向、MDE、类别)。t_wide 只用源域标签,与靶域 oracle(附录 Q.4)性质不同:它是可部署的第二种工作点策略,不是上界。
